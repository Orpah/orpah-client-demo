# ATECC608B 安全元件（c4-γ-2）：接线、命令来源、判据

> 这一步**只做一件事**：把 `payload.nonce` 的来源从**软熵**换成本仓 ATECC608B 的
> `Random(0x1B)`（规范 §5.4 要求 nonce 来自 SE 的 RNG）。
> **签名仍然是软件 P-256 替身** —— Slot0 私钥 / `Sign` / Config 锁 / 产线烧录都是 **d 步**。
> 这两件事必须**分开说**：`se` 命令与固件横幅里会同时打出 `se=stand-in(software P-256)`
> 和 `nonce_src=se|soft`，读的时候别合并成一句“已启用 SE”。

## 2. 唤醒与看门狗（这几个数都是**下界**，来自你自己的摘要手册 §2.3 / 表 2-2）

| 参数 | 最小 | 含义 |
|---|---|---|
| `tPU` | 100 µs | 上电后到可以拉 SDA 的时间（"上电自检使能时会**长得多**"） |
| `tWLO` | 60 µs | 把 SDA 拉低这么久（唤醒脉冲） |
| `tWHI` | 1500 µs | SDA 拉高后到可以发数据（**未使能自检**的情形） |
| **`tWHIST`** | **20 ms** | ★ **使能自检**时的同一个等待 ⇒ 这时 1.5 ms 远远不够 |
| `tWATCHDOG` | 0.7 / 1.3 / 1.7 s | 唤醒后这么久没收到**合法命令**就自己回睡 |

★ **`tWHI` 的说明里那句"unless polling is implemented"是救命的**（2026-09-22 逐字核表 2-2 才发现）：
手册**明确允许**用"轮询"代替干等满这个时长 —— 也就是**发一次唤醒令牌、没 ACK 就等一会儿再发**。
我们原来**只等 1700 µs、且只发一次令牌** ⇒ 一颗**完全正常但自检使能**的芯片会一直回 NACK，
现象恰好是「`nack` 逐帧 +1 而 `timeout=0`」（总线全好、器件就是不应答）。
⇒ `Periph/atecc.c` 的 `atecc_wake()` 现在**每轮重做整段序列（脉冲 + tWHI + 令牌）、最多 6 轮**
（标称 ≈21 ms 的忙等，而 `i2c_delay_us()` 实测比标称慢 4~5 倍 ⇒ 真实窗口 ≈85~100 ms，覆盖 20 ms）；
`se` 的判据行会打 `tries=N/6` —— **"第几次才 ACK"就是这颗芯片到底要等多久的实测值**。

⇒ 我们 60 s 才发一条 ID，**每条命令前都必须重新唤醒**（`Periph/atecc.c` 就是这么做的）。
唤醒**不是靠猜时间**：拉完脉冲后发一个"唤醒令牌"（I²C 写地址 `0x00`），**收到 ACK 才算醒** ——
这是 CryptoAuthLib `hal_check_wake()` 的做法。

⚠ 拉低 SDA 那一下必须**先把 I²C 外设关掉**（`i2c_disable()`）：否则外设会把
"SCL 高时 SDA 下降"当成一次 START，后面等 `SB` 就会在错的时刻满足。

## 3. 命令集：我们手上没有 NDA 版手册，用公开实现（**逐条标出处**）

`D:\Downloads\ATECC608B.pdf` 是 **Summary Data Sheet**（28 页），开头就写明
"The complete document is available under NDA" ⇒ **它没有命令集**。所以命令层的事实
取自同厂开源的 CryptoAuthLib（`MicrochipTech/cryptoauthlib`）：

| 事实 | 值 | 出处 |
|---|---|---|
| `Random` 命令码 | `0x1B` | `lib/calib/calib_command.h`（`ATCA_RANDOM`） |
| 模式 | `0x00` 自动更新种子 / `0x01` 不更新 | 同上（`RANDOM_SEED_UPDATE` / `RANDOM_NO_SEED_UPDATE`） |
| 返回数据长度 | 32 B | 同上（`RANDOM_NUM_SIZE`） |
| 无数据命令包长 | `ATCA_CMD_SIZE_MIN` = count+opcode+param1+param2+CRC = **7**（不挂 CRC 时 5） | 同上 + `lib/calib/calib_command.c` 的 `atCalcCrc()` |
| 命令最多耗时 | 23 ms（另一张表 50 ms） | `lib/calib/calib_execution.c` |
| CRC 算法 | poly `0x8005`、初值 0、**MSB-first** | `calib_command.c` 的 `atCRC()`：`crc_bit = crc_register >> 15; crc_register <<= 1` |
| CRC 线上字节序 | **小端**（低字节在前） | 同上：`crc_le[0] = crc & 0xFF` |
| 响应 count | 32 B 数据的响应 = `ATCA_RSP_SIZE_32` = **35**（这是 CryptoAuthLib 内部计数口径） | `lib/calib/calib_command.h` |

★ 上面那个 CRC 就是 **CRC-16/BUYPASS**（CRC 目录里的标准项）⇒ 它的**目录校验值**
`"123456789" → 0xFEE8` 被我们当作**外部黄金向量**钉在 `proto/crc16.c` 与
`proto/atecc_cli.c selfcheck` 里 —— 不是"我们自己算的、自己验的"。

## 4. 两处**待上机确认**的假设（写在这里，不要猜）

1. **响应 count 的口径**：我们按"`count` = 4（大端 count 自身）+ 32（数据） [+2（CRC）]"
   实现 ⇒ 期望线上读到 **36**（无 CRC）或 **38**（带 CRC）。
   CryptoAuthLib 内部那个 `ATCA_RSP_SIZE_32 = 35` 是它**存进缓冲后**的计数口径，
   两者不是一回事；真机上如果对不上，`se` 命令会把**实测的原始字节和长度打出来**
   （`[se] Random FAILED … last_resp_len=… raw=…`）—— 按它改常量，**别连试好几轮**。
2. **线上要不要挂 CRC**：取决于芯片 Config 区 `ChipMode` 的 I2C-CRC 位，而我们的摘要手册
   没给这个默认值 ⇒ 不猜：`atecc.c` **先按不挂 CRC 发一条，count 不是 36 再按挂 CRC 发一条**，
   哪一种通就**记住**（`se` 命令会显示 `no-crc(响应 36 B)` 或 `crc(响应 38 B)`）。
   判定结果请记到这里（下面第 6 节），下次就不用再判。

## 7. 如实边界（别包装成"已支持"）

- **签名不是 SE 做的**：`level=0` 仍是演示级的软件 P-256 ⇒ `se_ok` 仍为 1 的含义
  只是"能做 ES256"，与"SE 在签"**不是一回事**。
- **唤醒脉冲宽度没上示波器**：靠忙等（`i2c_delay_us`，近似、只保证"至少"，
  并且两处约束都是**下界**所以宁可长）；**没有实测过真实宽度**。
- **I²C 时钟假设 APB1 = 8 MHz**（无 PLL、无分频）。改主频/分频要同步改 `Periph/i2c.c`
  里的 `I2C_FREQ_MHZ`，否则会表现为地址 NACK 或读出全 `0xFF`。

## 8. 逐颗验收（2026-09-23）：一颗芯片一行判据

这一轮把**软件侧能自证的都证完了**，SE 仍然**零电气响应**。已排除项（每一条都有可复跑的判据）：

| 已排除 | 怎么排除的 |
|---|---|
| 线序 / 哪只脚在哪 | `seline` 把 SCL/SDA 当 GPIO 开漏翻转（**SCL 2 Hz / SDA 1 Hz**）⇒ 逐脚量：`pin6` 快翻转 = SCL 网、`pin5` 慢翻转 = SDA 网、`pin8` = 3.3 V、`pin4` = 0 V，与手册表 1 一致 |
| 供电 | 同上（`pin8` 实测 3.3 V、`pin4` 0 V） |
| 上拉 | 4.7 kΩ ×2 到 3V3（两线静态都是高） |
| 速率 | 100 kHz 与 50 kHz 都试（`seclk`） |
| 唤醒语义 | 改成"轮询 + 最多 6 轮"（§2），仍无 ACK |
| **地址** | `sewake` 扫 `0x01~0x7F`（脉冲前后各一遍）⇒ **没有任何地址 ACK** |
| 驱动层 | 全程 `timeout=0`（没卡在等待里），`nack` 计数与"NACK"一致 |
| 单次 ACK（`0x64`） | ★ **现场只出现过一次**：`sewake` 扫到 `0x64(ACK)`，紧接着 Info/Read/Random 全 NACK。⇒ 判定为**偶然**（见 8.1 第 4 条），不当器件 |

★ 这一轮**真抓出一个固件 bug**（就是这条工装的价值）：`i2c_probe()` 原来**先等 `SB` 再发 START**
⇒ 每次探测都白等到 20 ms 超时 ⇒ `ok` 恒为 0、`nack` 与 `fail` 同步 +1（提交 `b28a78b` 已修）。

### 8.1 一条命令出结论：`sewake`

```
sewake
```

打印（下面示例是"有芯片且未锁"的样子，逐字照 `Periph/atecc.c` 里的格式串）：

```
[sewake] I2C=100 kHz，命令地址当前=0x60
[sewake] 空闲电平：SCL=1 SDA=1（**都该是 1**；有一个是 0 ⇒ 那根线被按住，后面的 ACK 就不一定可信）
[sewake] ① 未脉冲：扫 0x01~0x7F（每址 3 探，≥2 次 ACK 才算）-> 0x35(ACK 3/3) （共 1 个）
[sewake] ★ 器件在 0x35 ⇒ 已把命令地址改成它，接着逐项验：
[sewake] ③ Info(0x30)  -> ok(无CRC)：00 00 60 03   ← 器件版本
[sewake] ④ Read cfg@0x54 -> ok(无CRC)：55 00 00 00   ⇒ **配置区 unlocked（0x55）**
[sewake] ⑤ Random(0x1B) -> ok：前 16 B = …
[sewake] ===== 结论：addr=0x35 rev=ok cfg=unlocked random=OK =====
```

**只看最后那一行**：

| 结论行 | 含义 | 处置 |
|---|---|---|
| `addr=0x00 … random=失败` | 整条总线**没有任何地址**应答 ⇒ 器件侧没反应 | 换下一颗；若颗颗如此，查焊接 / 供电 / 坏件（**"地址写错"已排除**） |
| `addr=0xNN rev=ok cfg=unlocked random=OK` | **这颗能用**（地址 = 0xNN） | 记下 NN：`seaddr NN` 钉住，或把 `i2c.h` 的 `I2C_ADDR_ATECC` 改成它 |
| `… cfg=locked … random=OK` | 别人锁过，但 **`Random` 照样能用**（锁只挡**写**，不挡读/随机） | 本步（γ-2 只要 nonce）**可用**；到 **d 步**要写 Slot0 就必须换颗未锁的 |
| `rev=无`（有地址但读不出信息） | 应答了、但不按 ATECC 协议回 ⇒ 多半是**别的器件占了这个地址** | 记下地址；别当它是可用的 SE |

★ 另外看**空闲电平那一行**：只要有一个是 0 ⇒ 先查那根线（被按住/搭到 GND/虚焊），
**不要**在那种状态下得出\"器件是坏的\"的结论。

★ **单次 ACK（`仅 1/3`）该怎么读**：它证明\"**这条线上确实有东西答过一次**\" ⇒ 连接不是全断，
而是**时通时不通** —— 这正是**虚焊 / 排针接触不良 / 转接板压不紧**的典型签名。
处置：① 重烫那一颗的 8 只脚（尤其 `SDA`/`SCL`/`GND`）；② 再连跑几次 `sewake`：

- 偶发几次、地址还可能变 ⇒ 基本就是焊接/接触问题；
- 每次都稳定同一个地址，但 Info/Read 全 NACK ⇒ 那地址上是**别的器件**（或该芯片已不按 ATECC 协议回）；
- 一次都不再出现 ⇒ 当偶然处理，但先把那 8 只脚补烫一遍再判。

★★ **2026-09-23 当天更新：上面这段里“单次 = 虚焊”的读法被现场推翻了。**
用户随后报告那个 `0x64` 的 ACK **100% 可复现** ⇒ 它不是毛刺，而是**一个稳定应答的东西**。
所以：**“一次 ACK”只能说明“还没测够”** —— 要分清楚必须靠**重复采样**，
这就是下面 `sescan` 存在的原因。
（注：那块板是**当天刚焊好的**；而 100% 复现说明 **“虚焊”这个解释也站不住** ——
成因到现在**仍未查明**，已知仅“答地址、但 `Info(0x30)` 不过”。）

三条实现上的讲究（也在 `Periph/atecc.c` 的注释里）：

1. **扫 `0x01~0x7F`，跳过 `0x00`**：`0x00` 是"唤醒令牌"的写地址，探它会把两种含义混在一起
   —— 而手册第 13 页写明 608B 的 I²C 地址**上锁后可编程**，所以**不能假定 0x60**。
2. **① 命中就不再脉冲**：器件本来就醒着；脉冲是留给"一个都不应答"那种情形的（少一次折腾）。
3. **一个都扫不到时也不早退**：照样在旧地址上写一条命令、**照样打结论行**
   —— ① 万一是探测本身有毛病；② 一颗芯片一行判据，逐颗试的时候不用去分辨"没打结论"是哪种情形。
   （配套：`random_try()` 改成**令牌没 ACK 不早退** —— 器件若已在 Idle，它对 `0x00` 本来就会回 NACK。）
4. ★ **一次 ACK 不算命中（2026-09-23 实测教训）**：现场出现过**仅一次**应答 `0x64`、
   随后 Info/Read/Random 全 NACK。而探针一趟只发一次地址 ⇒ **一次毛刺就能冒充器件**
   （第九个时钟采样到低就是"ACK"，SDA 被按住/线容/噪声都可能造出这一下）。
   现在每个地址**探 3 次、≥2 次 ACK 才算命中**；只 ACK 一两次的会打成
   `[0x64 仅 1/3 ⇒ 偶然，不当器件]` —— **当线索留着看，不当结论**。
   同时先打一行**两线空闲电平**：有一个是 0 ⇒ 那根线被某处按住，
   而这种状态恰好就是"偶然 ACK"的温床（先修线，再谈器件）。

### 8.2 其它三条工装

| 命令 | 用途 | 读法 |
|---|---|---|
| `sescan [n]` | **重复扫描统计**：一轮 = 完整唤醒序列 + 扫 `0x01~0x7F`；默认 10 轮、上限 60 | 末几行的表 + 结论行，见下 |
| `seline [1-9]` | SCL/SDA 当 GPIO 开漏翻转 N 秒（**SCL 2 Hz / SDA 1 Hz**） | 逐脚量：快翻转 = SCL 网、慢翻转 = SDA 网、恒高 = VCC、恒低 = GND、不动 = NC |
| `seclk <khz>` | 运行时改 I²C 时钟（10~400 kHz） | 唤醒令牌必须 ≤ 100 kHz |
| `seaddr <hex>` | 改命令用的 7 位地址 | `sewake` 扫到谁就自动设成谁；也可手动钉住 |

`sescan` 把三种情形**一眼分开**（这是“一次 ACK”做不到的；就不用拿示波器去抓那一下了）：

| 表里看到 | 结论行 | 含义 |
|---|---|---|
| `0xNN：N/N 轮` | `**稳定器件 0xNN**` | 线上有个**稳定**应答的东西 ⇒ 接着 `sewake` 逐项验（Info/锁/Random） |
| `0xNN：k/N 轮`（k<N） | `**不稳定**` | **时有时无 = 虚焊/接触不良的典型签名** ⇒ 先重烫那 8 只脚再跑 |
| 表为空 | `连着 N 轮一个地址都没答过` | 真没反应（不是“偶然没答”） |
| — | `唤醒令牌：k/N 轮 ACK` | 额外一栏：令牌本身就探 `0x00`，它的 ACK 率是**独立的**一个接触指示灯 |

### 8.3 采购与验收（买回来先跑哪几条）

拆机 / 散新件最常见的三种"还能用但不像新的"：

- **已被锁**：只挡写（`sewake` 的 `cfg=locked` 看得见）。
- **被改成 SWI 配置**（`SSHCZ` 系列）：数据只走 `pin5` **一根线**、`pin6` 变 GPIO、
  时序是 UART 形（230400-7N1）⇒ **我们这套硬件 I²C 完全用不了**，而且它在 I²C 上
  **一个地址都不应答**（在 `sewake` 里与"坏件"长得一模一样 —— 分不出来，只能靠外观/丝印/批号）。
- **地址被改成非 `0x60`**（手册第 13 页允许）：`sewake` 的 `addr=` 看得见。

⇒ 收货一律先跑 `sewake`：`cfg=` 分锁没锁、`addr=` 分地址、`random=OK` 才算"能干活"。

## 9. 未做 / 边界（本轮，如实）

- **§6 那张"上机判据"表一张都没填**（本轮一颗芯片都没应答）。
- `sewake` 新加的 `Info(0x30)` / `Read(0x02)` 两个命令包，
  **形状**照 CryptoAuthLib 的 `atcab_is_locked()`（含"配置区 word 0x15 的**字节地址 = 0x54**"
  这一推断 —— 因为 `Read` 的地址必须是 4 的倍数，而 word 0x15 不是）；
  **已做主机对拍**（`atecc_cli info|read|resp4` 与 Python 参考零偏差，同一套 CRC 参考，
  见 §5 的做法），**但没在任何真器件上验收过** ⇒ 真机若读出来不是 `55 00 00 …`，
  **先怀疑这个地址推断**，别急着重焊。
- 这些命令是**工装级**：形状的"正式向量"（进 `test_vectors_atecc.txt`）还没加 ——
  等 d 步做正式命令层时与向量一起补（现在由 `atecc_cli selfcheck` 的 ⑧⑨ 两类不变量守形状）。
- `sescan` 的 I²C 传输层在主机测试里是**桩件**（`i2c_probe` / `wake` 被替换）
  ⇒ 验的是**统计与判据**（稳定 / 时有时无 / 全无 / 默认轮数 / 上限截断），不是电气层。
- `sewake` 的 I²C 传输层在主机测试里同样是**桩件**（`i2c_probe` / `transact` 被替换）
  ⇒ 验的是**编排**（扫描顺序、地址切换、结论行、返回码），**不是**电气层。
- `0x64` 那个稳定 ACK **成因仍未查明**：已知“答地址、但 `Info(0x30)` 不过”。
